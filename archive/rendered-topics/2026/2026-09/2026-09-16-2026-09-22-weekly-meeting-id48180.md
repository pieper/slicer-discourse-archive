<h3><a name="p-135943-slicer-in-webassembly-2" class="anchor" href="#p-135943-slicer-in-webassembly-2" aria-label="Heading link"></a>Slicer in webassembly</h3>
<p>This is experimental work done by Andras over a weekend. All of Slicer, except for Qt, compiled into webassembly and running in a browser! No rendering or computations happen on the server, everything is done locally in user’s the browser, no data leaves the user’s computer.</p>
<p>Python is well supported. Python runs in the browser using Pyodide. The web application has a Python console, Python packages can be installed anytime (pip_install installs packages work from the Pyodide distribution, from PyPI through micropip, or from custom-built packages).</p>
<p>Scripted modules work without changes. Claude created a mock Qt layer to make this pretty seamless.</p>
<p>C++ modules work with no changes to MRML and logic classes. Shared Qt widgets are reproduced by Claude using Vue. Module-specific widgets are recreated by Claude.</p>
<p>Extensions are supported. All extensions that contain only Python scripted modules should work without any source code changes (just need to be repackaged). Very complex extension that contain VTK and ITK based compiled code work well, too (see for example VMTK).</p>
<p>The amount of code generated to achieve this was very small – this is not a re-implementation of everything but reuses the same C++ components that make up Slicer. The only source code that is not shared between desktop and web builds of Slicer are the Qt widgets.</p>
<p>This shows how much can be achieved in a short time in terms of porting slicer functionality to the web browser, and how mature webassembly and pyodide are.</p>
<p>Next steps: integrate necessary patches into upstream repositories, extend to include more modules and extensions.</p>
<p>Code is available at: <a href="https://github.com/lassoan/SlicerWeb" class="inline-onebox">GitHub - lassoan/SlicerWeb: Run 3D Slicer natively in the web browser · GitHub</a></p>
